# React Architecture (Netdust)

The stack layer `netdust-agent`'s harness defers to on a Vite + React + TypeScript app shipped to iOS and Android via Capacitor.

## 1. The shape

One app. Not a monorepo — a monorepo earns its place when there is a second consumer of shared code, and not before.

```
project-root/
├── android/                  # generated by Capacitor — committed, not hand-edited
├── ios/                      # generated by Capacitor — committed, not hand-edited
├── public/
├── src/
│   ├── features/<feature>/   # the unit of work
│   │   ├── components/
│   │   ├── hooks/
│   │   ├── schema.ts         # Zod — the feature's data contract
│   │   ├── storage.ts        # THE ONLY place this feature persists
│   │   └── index.ts          # the feature's public surface
│   ├── components/ui/        # shared primitives (shadcn) — no feature logic
│   ├── lib/                  # genuinely shared, feature-free helpers
│   ├── pages/                # route components; compose features, own no logic
│   ├── App.tsx
│   └── main.tsx
├── capacitor.config.ts
├── tsconfig.json
└── vite.config.ts
```

**Rules of the shape:**
- A feature owns its components, hooks, schema, and storage. Cross-feature imports go through `index.ts`, never into a feature's internals.
- `pages/` composes; it does not decide. If a page grows logic, that logic belongs in a feature.
- `components/ui/` is primitives only. The moment a "primitive" knows about a domain concept, it is a feature component.
- Do **not** grow a global `hooks/` bucket of unrelated hooks. That is where feature logic goes to hide.

Adapt to a project's existing layout rather than restructuring it mid-feature. A layout migration is its own task, planned as one.

## 2. The gates the harness runs

| Gate | Command | When |
|---|---|---|
| Tests | `npx vitest run` | every code task close |
| Typecheck | `npx tsc --noEmit` | every code task close |
| Lint | `npx eslint .` | every code task close |
| Format | `npx prettier --check .` | pre-commit (lefthook) |
| Dead code | `npx knip` | pre-push, and before "this is clean" |
| Browser E2E | `npx playwright test` | phase boundaries |
| **Device pass** | `npx cap run ios` / `android` | **before any shake-out claims the feature works** |

Typecheck is the cheapest high-yield gate on this stack — a React refactor that breaks a prop contract usually fails here and nowhere else.

## 3. Storage — the rule people get wrong

**`localStorage` compiles, tests green, and loses user data on iOS.**

It exists in the WebView, so nothing warns you. But WKWebView's storage sits in a cache the OS may evict under storage pressure, and it does not survive uninstall/reinstall. For a journal, a streak, a set of goals — anything a user would grieve — that is data loss, not a caching detail.

| Need | Use |
|---|---|
| Small key/value that must survive | `@capacitor/preferences` |
| Larger or queryable sets | SQLite (`@capacitor-community/sqlite`) |
| Genuinely disposable UI state (last tab, dismissed banner) | `localStorage` is fine |
| Secrets, tokens | secure storage — never `localStorage`, never `Preferences` |

**The convergence point:** every persistent read and write for a feature goes through that feature's `storage.ts`. One module, one place.

```ts
// features/check-in/storage.ts — the ONLY place check-in data is persisted.
import { Preferences } from '@capacitor/preferences'
import { checkInsSchema, type CheckIn } from './schema'

const KEY = 'check-ins/v1'

export async function loadCheckIns(): Promise<CheckIn[]> {
  const { value } = await Preferences.get({ key: KEY })
  if (!value) return []
  // Parsed, not cast: data written by an older build is untrusted input.
  const parsed = checkInsSchema.safeParse(JSON.parse(value))
  return parsed.success ? parsed.data : []
}

export async function saveCheckIns(checkIns: CheckIn[]): Promise<void> {
  await Preferences.set({ key: KEY, value: JSON.stringify(checkInsSchema.parse(checkIns)) })
}
```

Why this matters beyond tidiness: scattering `localStorage.getItem` across twenty components turns "move to durable storage" from an edit into a rewrite. It is also the single invariant most worth naming in a project's `ARCHITECTURE-INVARIANTS.md` — *"all persistence for feature X converges on `features/X/storage.ts`"* — because a reviewer can then check bypasses mechanically.

**Note the async seam:** `localStorage` is synchronous, `Preferences` is not. A codebase that reads storage synchronously during render has to change shape to migrate. Plan for async from the first feature even if v1 stays on `localStorage`.

**If a project deliberately keeps `localStorage` for v1** — a legitimate call, and a real privacy benefit since nothing leaves the device — write the acceptance into the project's `memory/STATE.md` along with the data-loss consequence, so it is a decision on record and not an oversight waiting to be discovered by a user.

## 4. The web/native seam

The same bundle runs in a desktop browser and in a WebView. These differ in ways your tests cannot see.

- **Guard native calls**: `Capacitor.isNativePlatform()` before anything platform-specific.
- **Clean up listeners** in the `useEffect` return. React 18 strict mode double-mounts in dev specifically to expose missing cleanup — treat a duplicate-listener bug as the check working.
- **Safe areas**: notches and home indicators need `env(safe-area-inset-*)`. A layout that looks right in the browser can put a button under the home bar.
- **The Android back button** is a real event (`@capacitor/app` `backButton`) with no browser equivalent. Unhandled, it exits the app mid-flow.
- **Keyboard behaviour** differs from the browser: it overlays content rather than resizing the viewport. Bottom-anchored inputs need explicit handling.
- **`npx cap sync`** after every dependency or config change.

For the React-side mechanics of all of this — hooks, listeners, deep links, platform rendering — use the `capacitor-react` skill.

## 5. State

| Kind | Home |
|---|---|
| Server state | TanStack Query — and only if there IS a server |
| Form state | react-hook-form + Zod resolver |
| Persistent local state | the feature's `storage.ts` |
| Ephemeral UI state | `useState` in the component that owns it |
| Cross-feature shared state | React context — and question whether the coupling is real |

Do not add a state library until the requirements force it. On a small app with device-local data, TanStack Query plus `useState` plus a storage module covers nearly everything; reaching for Redux or Zustand first is how a 6,000-line app acquires 12,000 lines.

## 6. Reviewing a change on this stack

Beyond what `netdust-agent:reviewer` covers generically, check:

1. Does any component reach `localStorage`/`Preferences` directly instead of through its feature's `storage.ts`?
2. Is anything read back from storage cast rather than parsed?
3. Does a new `useEffect` registering a Capacitor listener return a cleanup?
4. Does a native-only call sit behind a platform guard?
5. Does a new fixed-position element account for safe-area insets?
6. Did anything land in `components/ui/` that knows a domain concept?
7. Is a new dependency actually used, or did knip just gain another entry?
