## Blocking

1. `plugins/netdust-gates/bin/shakeout-check.py:308` (and the copy at `bin/feature-report.py:133`) — a new test title added to a spec file registered only under an earlier feature escapes the proof: `(path in earlier and path not in mine) or _redriven_by_git(…)` short-circuits on the registry and never asks git. `agents/shakeout-qa.md:149-150` ("never add a second row") makes this the common shape of extending a surface. Probe: a new title in an earlier-only `productions.spec.ts`, no log → `0 new row(s) proven, 2 re-driven`, PASS. Fix: one shared function `row_is_redriven(root, path, title, registry, feature)`: when git has a base copy of the file, the title decides (present → re-driven, absent → new); a file absent from the base → every row new; the registry decides only without a repository. Test `test_new_title_in_an_earlier_only_file_needs_its_proof`. [whole-branch C1]
2. `plugins/netdust-gates/bin/revert-run:64-73, :92, :116-129` — a failed restore is silent: with `.git/index.lock` held at restore time (the owning session committing, or a stale lock), the run logs `assertion-failed`, exits 0, and leaves base code in the tree and staged (reproduced). Fix: after the restore, `git status --porcelain -- <swap set>` must be empty; otherwise print the paths and the recovery command, write no log, exit 2 (one retry after a short sleep first). Test with a lock left by the test command. [security-sentinel H1]
3. `plugins/netdust-gates/bin/revert-run:79, :81` — a SIGKILL (OOM, power loss) leaves base code in the tree AND the index, unmarked (reproduced: `M  src/a.txt` staged). Fix: swap the working tree only (`git restore --source=<base> --worktree -- <M,D>`, `rm -f` for A; restore `git restore --worktree -- <M,A>`, `rm -f` for D) so the index never leaves HEAD; write a sentinel `.git/revert-run.swapped` listing the paths before the swap, remove it after the verified restore, and refuse to start while it exists, printing the recovery line. Test: a KILL case asserting the index is untouched, the sentinel present and the next run refusing with the recovery message. [security-sentinel H2]

## Should fix

1. The credential scan — `shakeout-check.py:316-321, :339`: (a) `revert-run:124` writes the command with `printf %q`, which breaks the `CREDENTIAL` pattern for `Authorization: Bearer …`, `--user u:p`, `wp-login.php?…` (measured); (b) only logs of new, non-accepted rows are scanned, while every `*.revert.txt` is committed; (c) header lines `feature:`, `base:`, `swapped:` trip the scan on harmless paths (`swapped: …/app-password-reset/screen.php`); (d) the manifest scan strips the whole `Test:` marker, title included. Fix: one loop over every `shakeout/*.revert.txt`, scanning the `command:` line un-escaped and the excerpt (from `--- output:` on) only; the manifest scan blanks only the `Test:` PATH. Tests: an `Authorization: Bearer` in `%q` form, an orphan log, a path-shaped `swapped:` line, a secret in a title. [security-sentinel M1, L2; whole-branch I1, I2]
2. `revert-run:52, :70-71` — ignored files are destroyed: at a branch-deleted path (overwritten, then `rm -f`'d) and under a path the base has as a file and HEAD as a directory (the forced checkout removes the subtree). Fix: for every D path refuse when anything exists on disk (`[ -e "$p" ] || [ -L "$p" ]`); refuse a base-file/HEAD-directory clash. Tests for both. [security-sentinel M2; whole-branch I3]
3. The proof is forgeable — `shakeout-check.py:274-287` reads line 1 only: a copied log proves any row (probe), a hand-written one costs nothing. Fix: the checker requires the log's `test:` line to equal the row's `<path> :: <title>`, its `base:` to equal the current merge-base's short sha, and `exit:` non-zero for `assertion-failed`; the agent prompt says the file is `revert-run`'s output only. [security-sentinel M3; whole-branch M1]
4. `revert-run:16, :114-115` — `<feature>` is unvalidated: a `/` or `..` writes the log outside `specs/`. Fix: `case $feature in ''|*/*|.|..|-*) refuse`. [security-sentinel L1]
5. `revert-run:87` — `on_signal` TERMs the direct child only; a grandchild (a Playwright browser) keeps running against the restored site. Fix: run the command in its own process group (`setsid`) and kill the group. [whole-branch M3]
6. `shakeout-check.py:269-271` — the per-row git match is a bare substring: a `test.describe('credits heading')` in the base makes a new `test('credits heading')` re-driven (probe). Fix: anchor on the call — `\b(?:test|it)(?:\.\w+)*\s*\(\s*['"\`]<title>['"\`]` for Playwright, `function\s+<title>\s*\(` for PHPUnit. [whole-branch M2]
7. Wording: `make report` and policy step 6 say "commit `report.md` and `specs/CHECKS.md`" (the trial line lands in the registry) [M4]; policy step 3 restores "copied from `make review`'s saved report" for `review.md` [M8]; `shakeout-qa.md` names `Hunt: deferred — runs at the feature's end` for an intermediate slice so `make shakeout` does not bounce [M5]; `--grep` titles are regex-escaped [M7].
