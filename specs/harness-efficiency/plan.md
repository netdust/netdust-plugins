## Design detail (what the tasks build to — no placeholders downstream)

### D1 — The `Test-author:` field (grammar + gate-check rules)

Per-task grammar (one continuation line per task, indented like `Unit test:`):

```
Test-author: split                       # independent test-author dispatched BEFORE the implementer (unchanged pair protocol)
Test-author: solo — <one-line reason>    # single implementer authors its own RED-first test; reason mandatory for Tier A
```

Decision rule the planner applies (D1-rule, cited by T02/T03/T06): `split` iff the task is Tier A **and** in a security-boundary category — auth/guards/capability checks, untrusted-input parsing, migrations/schema, money/billing, or any 1a-trigger surface named in the plan's threat model. Tier A outside those categories ("A-lite": pure logic/transforms/thresholds) → `solo — <reason>`; Tier B → `solo — Tier B` (reason may be the tier itself). The controller READS this field; no run-time agent re-decides it (invariant #1).

`gate-check.py` new check (id `test-author-mode`), added beside `check_task_tiers`:

| Condition | Verdict |
|---|---|
| No task in the file carries a `Test-author:` line | WARN `pre-0.8 tasks.md — no Test-author: lines` (never retro-fail old dirs) |
| Some tasks carry it, some don't | FAIL, naming the bare task ids |
| Value not `split` or `solo…` | FAIL |
| `[Tier A]` task with `solo` and no reason text after a dash | FAIL `Tier A solo requires a stated A-lite reason` |
| `[Tier B]` task with `split` | WARN `over-ceremony — split is for security-boundary Tier A` |
| All present and coherent | PASS `all N tasks carry a test-author mode` |

Continuation-line scan: lines between a matched `TASK_LINE` and the next task line / heading / fence, matching `^\s+Test-author:\s*(split|solo)\b\s*(?:[—-]\s*(.*))?$`. Fenced blocks stripped with the existing `strip_fenced`.

### D2 — Tier-conditional dispatch (prose contract for T03/T04/T05)

- **Split path:** byte-for-byte today's protocol (test-author RED → implementer GREEN, two commits, both addenda, reconciliation in Step 2.6). Fires ONLY for `Test-author: split` tasks.
- **Solo path:** ONE implementer dispatch. RED-first remains the Iron Law — the implementer authors the behavioral RED itself (shell rule included), watches RED→GREEN, and its Test-evidence block records `Contract test author: self — solo mode (plan: Test-author: solo)` and `Weakened? n/a — self-authored (solo mode)`. The `subagent-stop.py` backstop is untouched (it checks that tests ran; it never checked authorship). The independent check for solo tasks is NAMED where the enforcement ledger lives: the cluster review gate + the phase-close test-effectiveness audit — the two controls that caught all real bugs on 2026-07-04.
- **Class E:** default solo (controller may still author the RED inline for a trivial change); anything touching a security-boundary file is Class D, which is always split (its diff threat model names the contract the test-author asserts).
- **Class C:** a review finding on a 1a surface → split (the reproduction is authored independently); other findings → solo reproduction, same one-cycle-per-bug rule.
- **Enforcement honesty (ledger updates):** the split's "SEQUENCER-ENFORCED" paragraph gains: *the tier boundary itself is MACHINE-CHECKED (gate-check `test-author-mode`) at the seam; the controller reading it is sequencer-enforced; solo mode reintroduces self-authorship by design for non-security tasks and moves the independent check to the cluster review + test-effectiveness.*

### D3 — Presence-aware planning (prose contract for T07/T09)

Rule text (planning `<stage_persona>` + a red-flag row): *when the human is present and actively steering (interactive session, requirements still moving), plan INLINE in the main conversation — a pivot must cost a sentence, not a background-agent round-trip; dispatch the background `planner` (or plan-correction agents) only when the human has stepped away or the output feeds an unattended run (armed `/loop`, tmux loop, scheduled run). The review ladder before UNATTENDED execution — Stage 1.5 gate-check + human approval at the seam, plus `doubting-decisions` on the plan's key decision — is MANDATORY regardless of planning mode; presence changes where planning happens, never which gates fire.* Evidence lines (Sofie: two sub-10-minute pivots invalidating finished background plans; the pre-unattended ladder catching 4 loop-breakers) recorded as calibration `background-planner-pivots`.

### D4 — Class F intake (prose contract for T08/T09)

New intake row: **F — Shaping / vision-stage exploration** (no code will change this session) → `superpowers:brainstorming` + `refining-ideas` only; output at most a scope sketch / notes doc (`docs/notes/…` or the conversation itself); explicitly NO spec/plan/tasks artifact, NO gate ceremony, NO feature dir; promotion path named: when it becomes real work, re-enter intake as Class A (the notes feed Stage 0). Dial line gains `F = brainstorm only, notes at most`. Red-flag row: *"The user is describing a vision — I'll get a head start on the plan" → don't manufacture a plan artifact; a vision brief is Class F. Ceremony for work that won't change code this session is pure wait-time (teacher-app, 2026-07-04: 30+ min of unwanted planning).* Calibration slug `vision-brief-ceremony`.

### D5 — `run-trace.py show --durations` (T10)

`show` gains an optional `--durations` flag. Without it: byte-identical output to today (asserted). With it: after the normal rendering, print a segments table —

```
── durations ──
<event-a>[ <key data>] → <event-b>[ <key data>]   <H:MM:SS>
…
total (first → last parseable event)              <H:MM:SS>
```

one row per consecutive pair of parseable events (corrupt lines and lines with unparseable `ts` are skipped, consistent with `show`'s `<corrupt line>` behavior); `review-gate` rows include `cluster=/tier=`, `stage-enter` rows include `stage=`. Fewer than 2 parseable events → `durations: not derivable (<2 timestamped events)`, exit 0. No aggregation beyond the total — segments between the existing emission points ARE the per-stage/per-gate durations.

### D6 — `spec-kit/run-cost.py` (T11)

```
usage: run-cost.py <feature-dir> [--transcript-dir <dir>]
```

- **Default transcript dir:** `~/.claude/projects/<slug(cwd)>` per the ground-truthed slug rule; `--transcript-dir` overrides (varies per machine). Missing dir → print `no transcript found: <dir>`, exit 0.
- **Inputs (all read-only):** every `*.jsonl` directly in the dir (main sessions) + every `<session>/subagents/agent-*.jsonl` with its sibling `agent-*.meta.json` (agentType, description). A malformed line or absent meta.json degrades to skipping that line / labeling the dispatch `unknown` — never a crash.
- **Window:** if `<feature-dir>/run-log.jsonl` exists, the run window is [first event ts, last event ts]; only dispatches whose first line falls inside it, and main-session assistant lines inside it, are counted. No run-log → per-dispatch report over the whole transcript dir + note `per-stage attribution skipped (no run-log.jsonl)`, exit 0.
- **Per-dispatch table:** one row per subagent (agentType, description, first ts, wall-clock last−first, model, Σ output_tokens, Σ cache_read_input_tokens, Σ cache_creation_input_tokens, Σ input_tokens over its assistant lines) + one `(controller)` row per main session for in-window assistant lines.
- **Per-stage table:** stage windows derived from run-log boundary events (`gate-check-green`, `stage-enter`, each `review-gate`, `loop-disarm-*`, and the literal manual-disarm event `loop-disarmed` — consecutive boundaries delimit segments); same boundary-event vocabulary as D5; run-cost segments over boundary events only (a subset of D5's all-events segmentation) — on boundary-only fixtures the windows coincide; each dispatch/controller-line attributed to the window containing its (first) timestamp; per-window Σ tokens + wall-clock.
- **Timestamps:** normalize both forms before parsing (`s.replace("Z", "+00:00")` → `datetime.fromisoformat`).
- **Never writes** anywhere except stdout; the read-only property over the transcript dir is a tested assertion (dir listing + mtimes unchanged), per invariant #2. Output is counts + metadata only — no message content (spec privacy note).
- Exit codes: 0 success incl. all degradation paths, 1 usage error — same discipline as `run-score.py`.
